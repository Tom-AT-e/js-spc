# Domain docs

This repo uses a single-context layout:
- GLOSSARY.md at the repo root for domain terminology.
- docs/adr/ for architectural decisions.

Before exploring, read the glossary and ADRs relevant to the task.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Use the glossary's terminology in issues, proposals, and code.
Note meaningful terminology gaps for domain-modeling.
Explicitly flag proposals that conflict with an existing ADR.
